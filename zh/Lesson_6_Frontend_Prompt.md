## 前端开发的核心在于用户体验

当你使用 AI 进行前端开发时，请牢记：**前端的灵魂是 UI 和用户体验**。这不仅仅是把界面做得漂亮（虽然颜值也很重要），更关键的是创造出用户真正喜欢并乐于使用的产品。

正因如此，你的 Prompt 必须在 UI 和用户体验的细节上做到极致。你可以这样想：如果你要聘请一位设计师，你绝不会只说一句“把它弄好看点”。你会和他深入探讨你的用户群体、他们的使用目标、你期望的交互方式，以及整个产品希望给人的感觉。当你给 AI 写前端 Prompt 时，道理是完全一样的。

## 好的 Prompt vs. 坏的 Prompt

我们来看看，一个糟糕的前端 Prompt 和一个优秀的 Prompt 究竟差在哪里。

### 糟糕的 Prompt 示例
“我想要一个显示步数的屏幕。”

这个 Prompt 基本上等于没说。AI 不得不靠猜来完成所有工作：这是什么平台的应用？界面应该长什么样？数据如何展示？步数从哪里来？这个页面需要跳转到其他地方吗？这就像你让一个装修师傅“给我盖个房间”，却不提供任何设计图、尺寸规格，甚至连房间的用途都不告诉他。

### 优秀的 Prompt 示例
“为 iOS 平台开发，使用 SwiftUI。我需要一个计步器的主屏幕，要求醒目地展示用户当前的步数。步数要大号字体、屏幕居中、并且能实时更新。在步数周围，要有一个类似 Apple Watch 活动圆环的圆形进度条，它会随着用户接近每日步数目标而填充。在主数据显示区的下方，用小一些但清晰的字体展示‘距离目标还差多少步’、‘已走距离’和‘燃烧的卡路里’。底部需要一个导航栏，包含‘历史记录’和‘设置’两个入口。字体请使用 SF Pro Display，图标使用 SF Symbols。”

这才像话！这样的 Prompt 给了 AI 构建一个实用功能所需的一切信息。

## 优秀前端 Prompt 的五大支柱

在撰写前端 Prompt 时，可以从以下五个关键维度来思考。虽然不是每个 Prompt 都需要面面俱到，但你提供的细节越丰富，得到的结果就越出色。

### 1. 技术地基 (Tech Stack)
这是你的技术基础，就像盖房子前要选好钢筋水泥。

- **平台 (Platform)**：你的目标是 iOS、Android、Web 还是桌面应用？
- **框架 (Framework)**：是 iOS 的 SwiftUI，Web 的 React/Vue，还是跨平台的 Flutter？
- **关键库 (Key Libraries)**：你会用 shadcn/ui 的 React 组件库，还是用 Bulma 写 CSS，或者有自己的设计系统？

**为何重要**：不同平台有其独特的设计规范和功能特性。一个 iOS App 就应该有 iOS 的味道，而不是一个生硬的“网页套壳”应用。

### 2. 布局与结构 (骨架)
这定义了屏幕上所有元素的组织和排列方式。

- **视觉层级 (Visual Hierarchy)**：什么内容最重要？你希望用户第一眼看到什么？
- **元素定位 (Placement)**：元素是按行、列、居中排列，还是遵循特定的网格系统？
- **特定组件 (Specific Components)**：你需要进度条、标签页、卡片、模态框，还是某些自定义组件？

**为何重要**：良好的结构能自然地引导用户使用你的界面；而糟糕的结构则会让用户感到困惑和沮丧。

### 3. 数据与状态 (大脑)
这部分涵盖了界面上需要展示什么信息，以及这些信息从何而来。

- **待展示数据 (Data to Display)**：是带单位的步数，还是用户个人资料，或是商品列表？
- **数据源 (Data Sources)**：数据来自 REST API、GraphQL，还是像 HealthKit 这样的设备传感器，或是本地存储？
- **边缘情况 (Edge Cases)**：数据加载时、发生错误时，或者没有任何数据显示时，界面应该如何响应？

**为何重要**：真实的应用处理的是真实的数据，而真实的数据往往是错综复杂的。充分考虑边缘情况，可以防止你的应用在意外发生时崩溃。

### 4. 交互与感知 (灵魂)
这部分为你的界面注入生命力，让它变得灵敏而有响应。

- **交互性 (Interactivity)**：当用户点击、滑动、滚动或悬停时，会发生什么？用户是否需要跳转到其他页面？
- **行为与动画 (Behavior & Animation)**：数据需要实时更新吗？是否需要下拉刷新功能？页面切换时需要平滑的过渡动画吗？
- **无障碍设计 (Accessibility)**：你的应用是否支持 VoiceOver、屏幕阅读器，或者能被有特殊需求的用户顺利使用？

**为何重要**：静态的界面是死气沉沉的。好的交互能让你的应用显得精致而专业。

### 5. 视觉美学 (颜值)
这是你的视觉设计——用户对产品的第一印象。

- **品牌风格 (Branding)**：你的主色调是什么？你遵循的是 Material Design、Human Interface Guidelines，还是有自己的品牌规范？
- **排版 (Typography)**：是否需要指定字体（如 SF Pro Display）、字号、字重？
- **图标 (Iconography)**：你用的是 SF Symbols、Feather Icons，还是自定义图标，或者有特定的图标风格要求？

**为何重要**：用户在毫秒之间就会对你的应用做出评判。出色的美学设计能建立信任感，让你的应用看起来更正规、更值得信赖。

## 撰写前端 Prompt 的高阶技巧

### 善用你的规划文档
还记得我们在第 3 课中提到的规划文档吗？你的 `requirements.md`、`system_design.md` 和 `todo_list.md` 是撰写前端 Prompt 的金矿。多参考它们，可以避免重复开发，确保组件的单一职责，并让你的代码库保持整洁和模块化。

### 迭代式优化 Prompt
别指望一次性就得到完美的结果。如果你在使用 VSCode 或 Cursor 并安装了相应插件，可以利用实时预览功能立即看到变更。先实现基本功能，然后优化设计，最后再添加交互。这就像雕塑一样，从粗略的轮廓开始，逐步雕琢细节。

### 尝试不同的“Vibe”
使用 AI 编码的一大好处是，你可以毫无压力地构建多个版本，然后挑选你最喜欢的那一个。大胆地让 AI 尝试不同的风格，看看哪个版本最有“Vibe”。

### 参考知名应用
与其费力描述每一个细节，不如直接参考知名应用。“像 Instagram 的快拍界面”或“类似 Spotify 的‘正在播放’屏幕”，这样的描述能让 AI 立刻领会你的意图。

### 借助视觉辅助工具
其他应用的截图、你手绘的线框图，或是 Figma 设计稿都极具价值。尤其是在讨论视觉界面时，一张图片真的胜过千言万语。

### 拥抱组件库
不要重复造轮子。使用像 shadcn/ui 这样成熟的 React 组件库，或者逐步建立你自己的组件库。我们会在后续课程中深入探讨这一点，但现在你只需知道：在 Prompt 中提及这些库，能让你获得更好、更一致的产出。

## 融会贯通

一个优秀的前端 Prompt，关键在于**足够具体**，能让 AI 精确构建出你脑海中的画面；同时又**留有余地**，让 AI 能处理那些你可能不了解的技术实现细节。

把自己想象成一位电影导演——你需要清晰地传达你的愿景，但不必亲自去操作摄像机或剪辑影片。你越能清晰地描述最终的用户体验应该是什么感觉，你的 AI 编程伙伴就越能帮你把它变为现实。

在下一课中，我们将深入探讨后端 Prompt，看看在处理数据、API 和服务器端逻辑时，我们的关注点会有何不同。但现在，就开始在你自己的项目中实践这些前端 Prompt 技巧吧。当你为 AI 提供了构建卓越用户体验所需的上下文后，你将惊讶地发现，产出结果的质量得到了惊人的提升。
