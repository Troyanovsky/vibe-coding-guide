## 为什么需要可复用组件

在用 AI 做大型项目时，你可能会注意到一些重复的模式：一遍又一遍地描述相同的按钮样式，反反复复地解释同一个配色方案，或者不厌其烦地告诉 AI 你想要的卡片布局。听起来是不是很熟悉？

这时候，可复用组件就能派上大用场了。你可以把它们想象成一套个人专属的设计或代码库，随时“喂”给 AI，让你的 Vibe Coding 过程更高效、更一致。

**可复用组件能从以下几个关键方面，极大地提升你的 AI 工作流效率：**

它们能确保整个原型设计的高度一致性。你再也不用担心每次让 AI 添加新功能时，得到的按钮样式会有些许偏差。你的用户界面（UI）将保持统一，就像在 Figma 这类传统设计工具中使用设计系统一样。

它们能减少重复的 Prompt，从而大大加快开发速度。你不需要每次都从零开始描述输入框的样式，只需引用你的模板文件，AI 立刻就能心领神会。

它们就像是 AI 助手的“迷你样式指南”。当你定义好组件后，AI 的输出会变得更加可预测。这好比是给你的 AI 合作伙伴一份清晰的项目视觉语言说明。

最重要的是，它们让你能够“一次定义，处处复用”。这就是 DRY（Don't Repeat Yourself）原则在 AI 辅助开发中的具体应用。

## 设计能让 AI “消化”的 UI 组件

那么，如何创建这些可复用组件呢？下面我将根据你的技术背景和熟悉程度，介绍三种不同的方法。

### 方法一：从设计工具入手（设计师首选）

如果你已经能熟练使用 Figma 等设计工具，那这条路子最适合你。你可以在 Figma 中创建自己的设计系统，或者从 Figma 社区里找一个符合你 Vibe 的设计系统来用。

你需要整理出以下内容：
- 常见的布局模式（页眉、侧边栏、内容区）
- 不同状态下的按钮样式（主要、次要、禁用）
- 包含标签和验证状态的表单输入组
- 模态对话框和警告信息
- 字体规范和间距单位

接下来就是见证奇迹的时刻：利用 Figma 的 Dev Mode。导出每个组件的代码，并将其保存为模板文件。例如，如果你在使用 Vue，就可以将它们保存为 `input_form_template.vue`、`button_template.vue` 等文件，并统一放在一个模板文件夹里。

这种方法能让你获得像素级精准的组件，既保持了设计的统一性，又能直接交给 AI 使用。

### 方法二：从 Vibe Code 开始（非设计师的福音）

不会用 Figma？没关系。你可以直接通过 AI 来构建你的组件库，过程相当简单。

首先，找一些和你正在构建的应用风格相似的参考 App。把你喜欢的 UI 元素截图，然后“喂”给 AI 助手。下面这个 Prompt 效果就很好：

```
请根据我提供的截图，使用 Vue 3 和 Tailwind CSS 帮我构建一个 Vue 组件库。请遵循以下步骤：

1. 分析截图，识别出不同的 UI 元素，例如：
- 按钮
- 输入框
- 导航栏
- 卡片
- 模态框
- 字体样式

2. 为每个组件：
- 创建一个 Vue 单文件组件（.vue 文件）
- 使用 Tailwind CSS 设置样式，尽可能地还原截图效果
- 确保组件具有响应式设计和良好的可访问性
- 添加 props 以提高灵活性
- 添加简短的注释来说明组件的用途

3. 将所有组件保存在 `templates/` 文件夹中。

4. 创建一个 `index` 页面，导入并展示每个组件及其使用示例。

注意：只使用自定义组件和 Tailwind CSS，不要使用外部 UI 库。优先考虑代码的可复用性和整洁的结构。
```

这里的关键是“迭代”。先预览结果，然后通过 Prompt 让 AI 不断优化，直到每个组件都达到你想要的样子。满意之后，再将每个组件保存为模板文件。

### 方法三（彩蛋）：借鉴他人成果

这算是个“秘密武器”。有一个叫“HTML to React & Figma by Magic Patterns”的 Chrome 插件，在开发 Web App 时特别好用。

它的用法是：打开任何你喜欢的网页，激活这个插件，选中你想要的组件，它就能把这个组件连同所有样式一起提取成一个 React 组件。是不是很酷？

拿到 React 代码后，你就可以把它“喂”给 AI 助手，让它转换成你项目所用的框架代码，然后保存为模板。

如果你想快速获得看起来很专业的组件，尤其是在构建与现有热门应用类似的产品时，这个方法简直是神器。

## 创建可复用的非 UI 组件

组件不仅限于 UI 元素。你也可以为代码库中任何重复出现的模式创建模板。

比如 API 端点的结构、数据库查询的模式、用户认证的流程，或是错误处理的方案。如果你发现自己总是在向 AI 重复解释同一套逻辑结构，那就把它变成一个可复用的模板。

例如，你可以创建一个文件，里面包含你标准的 API 端点结构，包括错误处理、数据验证和响应格式等。之后每当需要新的端点时，你都可以引用这个模板。

## 如何向 AI 提供你的素材和上下文

现在到了最关键的一步——如何高效地利用这些组件来配合你的 AI 助手。

**在使用 Cursor 这类工具时**，你可以用 `@` 符号直接引用你的模板文件。例如，输入 `@input_form_template.vue`，AI 就能立刻读取并理解你输入表单的组件结构。

**创建一个“项目风格指南”**（Project Style Guide）文档（推荐使用 Markdown 文件，就像我们之前讨论过的 `requirements.md` 一样），把它当作你的组件库说明书。这个文件应该包含：
- 何时使用哪个模板
- 常用模式的代码片段
- 通用的风格指南和个人偏好
- 你的模板文件的引用路径

你可以把这个风格指南看作是项目的“个性档案”，随时让 AI 参考。这就像和一位新同事沟通一样——你为他们提供了在项目规范内高效工作所需的全部背景信息。

关键在于要系统化地使用它们。不要创建完组件就抛之脑后，要把引用它们作为你 Prompt 工作流中的一个习惯。你越是坚持使用，AI 的输出就会越稳定、越一致。

## 让一切协同工作

真正神奇的地方在于，当你把定义清晰的可复用组件和前几课讲的结构化工作流结合起来时，你的 AI 辅助编程能力将得到极大的提升。

你的规划文档（`requirements.md`, `system_design.md`）定义了你要构建什么，你的组件库定义了它应该长什么样、如何工作，而你的 Prompt 则可以精准地聚焦于你需要的具体功能。

你不再需要每次都从零开始，而是在一个坚实的基础上添砖加瓦。AI 能够理解你项目的视觉语言、代码结构偏好和质量标准。这就像拥有了一位经验丰富、完全懂你的团队成员。

最终的结果是：开发速度更快，输出更一致，修改或添加新功能时也少了很多烦恼。你不再是随心所欲地 Vibe Coding，而是在有目的、有章法地进行 Vibe Coding。

在下一课中，我们将深入探讨如何利用 AI 进行测试和调试。当你有了这些可复用组件作为基础，测试和调试也会变得容易得多。
