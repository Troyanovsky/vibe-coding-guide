## 测试和质量检查为何至关重要

我们必须面对一个现实：AI 生成的代码并非完美无瑕。它虽然强大到能以前所未有的速度构建出可用的产品原型，但也容易引入一些难以察觉的 bug、性能瓶颈，甚至偶尔出现一些匪夷所思的行为。你可以把 AI 想象成一位才华横溢但略显粗心的同事——他能高效产出亮眼的成果，却偶尔会在重要邮件里留下错别字。

而测试和质量检查，就是你的“安全网”。它们能确保 AI 生成的应用不仅功能正常，在不同设备上表现良好，更不会在向关键人物演示时让你陷入尴尬。此外，学会与 AI 一同调试，就如同拥有了一位全天候在线、永不厌倦你任何问题的编程导师。

## 测试你的原型

### 手动测试：不可或缺的人工环节

在讨论高大上的自动化测试之前，我们先从基础做起。手动测试，顾名思义，就是由你亲自操作，点击应用的各个角落，确保一切正常。

**手动测试清单：**
- **视觉检查**：布局、颜色、字体和间距是否都符合设计预期？
- **响应式适配**：在手机、平板和桌面等不同尺寸的屏幕上，应用是否都能正常显示和工作？
- **流程完整性**：点击每一个按钮，填写每一张表单，走完每一个用户流程。
- **异常模拟**：尝试“破坏”它——提交空表单会怎样？连续快速点击按钮两次呢？输入一些奇怪的数据又会如何？

这个过程看似繁琐，但效果惊人。仅仅通过像真实用户一样使用你的应用，你就能发现绝大多数问题。

### 浏览器开发者工具：你的调试利器

所有现代浏览器都内置了强大的开发者工具（在 Chrome/Firefox 中，右键点击页面选择“检查”即可打开）。它们是定位问题的绝佳帮手：

- **Console (控制台) 标签页**：显示 JavaScript 错误和警告。
- **Network (网络) 标签页**：揭示 API 请求是否成功或失败。
- **Elements (元素) 标签页**：允许你实时查看并临时修改 HTML/CSS。
- **Responsive design mode (响应式设计模式)**：无需准备多台设备，即可模拟不同屏幕尺寸下的显示效果。

不必精通所有功能，你只需留意红色的错误信息，然后将它们复制粘贴给 AI 助手寻求帮助即可。

### AI 赋能的自动化测试

接下来是更有趣的部分。你可以直接让 AI 为你编写自动化测试脚本。例如，在开发一个 Web 应用时，你可以这样提问：

*“我有一个包含邮箱和密码输入框的登录表单。你能帮我写一个 Playwright 测试吗？要求是：当提交无效凭据时，检查表单是否会显示错误提示。”*

AI 能够生成端到端（E2E）的测试代码，自动模拟用户点击按钮、填写表单并验证结果。这对于那些需要反复执行的测试流程来说，尤其有用。

## 与 AI 助手并肩调试

### 理解常见的错误信息

在深入探讨 Prompt 策略之前，我们先熟悉一些常见的错误类型：

- **"undefined"**：通常意味着你试图使用一个不存在或尚未被赋值的变量。
- **"Syntax error"**：代码中存在语法错误，比如拼写错误、缺少分号或括号不匹配。
- **"TypeError"**：你尝试对某个数据执行了它不支持的操作（例如，试图在一个数字上调用函数）。
- **"404 Not Found"**：代码试图访问一个不存在的文件或 API 接口。

### 高效调试的 Prompt 技巧

当程序出错时，AI 助手就是你的调试伙伴。以下是如何向它高效求助的技巧：

**针对错误信息的 Prompt：**
*“我在控制台遇到了这个错误：`TypeError: Cannot read property 'name' of undefined`。这是相关的代码：`[附上你的代码片段或文件名]`。你能帮我定位问题所在吗？”*

**针对行为问题的 Prompt：**
*“当我点击‘提交’按钮后，预期行为是提交表单并显示一条成功消息，但现在点击后毫无反应。这是按钮和提交功能的相关代码，请帮我排查并修复问题。`[附上你的代码片段或文件名]`”*

**请求解释代码的 Prompt：**
*“你能解释一下这行 JavaScript 代码 `const user = users.find(u => u.id === userId)` 的作用吗？我正在试图理解为什么我的代码没有按预期工作。”*

关键在于：清晰地描述“预期行为”与“实际情况”的差异，并提供足够且相关的代码上下文。

## 借助 AI 定义测试

### 规划手动测试

即便你不打算编写自动化测试代码，AI 也能帮你规划手动测试的步骤。试试这样提问：

*“我有一个表单，包含一个邮箱输入框和一个提交按钮。我想测试当输入无效邮箱并点击提交时，是否会弹出错误提示。请为我描述一下手动测试这个功能的具体步骤，并考虑不同的用户流程和边缘情况。”*

*“根据这个产品卡片组件的需求文档 `[提及需求文档]`，我应该重点测试哪些功能点来确保它工作正常？”*

这能帮助你梳理思路，发现那些可能被忽略的边缘情况和测试场景。

### 生成测试用例

如果需要更结构化的测试，你可以让 AI 为你生成全面的测试用例：

*“这是我的用户注册流程：`[描述流程或提及需求文档的相关部分]`。为了确保这个功能的可靠性，我应该覆盖哪些最重要的测试用例？”*

AI 通常会建议你测试“happy path”（理想流程）、错误用例（无效输入）、边缘用例（输入为空）以及边界条件（例如输入超长字符）。

### 编写自动化测试代码

如果你对测试框架很熟悉，可以让 AI 直接生成测试代码：

*“请为这个用于验证邮箱地址的 JavaScript 函数编写一个 Jest 单元测试。测试需要覆盖有效和无效两种格式的邮箱地址。”*

切记，要清晰地定义你预期的输入和输出，并且最好让 AI 解释一下它编写的测试代码具体在检查什么。

## 代码质量基础与审查

### AI 生成代码的常见问题

AI 生成的代码虽然能用，但常常带有一些“个性”：

- **冗余（Verbosity）**：AI 有时会写出比实际需求更多的代码。
- **低效（Inefficiency）**：AI 给出的第一个方案不一定是性能最优的。
- **安全疏忽（Security oversights）**：AI 可能会忽略一些常见的安全最佳实践。
- **模式不一致（Inconsistent patterns）**：在同一个代码库里，不同部分可能采用了不同的实现方法。

### 代码质量审查的 Prompt 技巧

你可以通过以下方式，让 AI 帮助你提升代码质量：

**通用审查：**
*“可以帮我审查一下这段代码的清晰度吗？并提出一些建议让它更具可读性。另外，它是否遵循了 DRY 和 KISS 原则？”*
（关于这些原则，我们在 [第 2 课](en/Lesson_2_Tools.md) 中有详细说明）

**性能检查：**
*“这段 JavaScript 代码有明显的性能问题吗？我该如何优化它以提升效率？”*

**简化请求：**
*“这段代码虽然能用，但感觉过于复杂了。你能在保持功能不变的前提下，将它简化吗？”*

**可维护性优化：**
*“请重构这段代码，让它更易于维护。请优先使用简单的函数，而不是复杂的类继承结构。”*

### AI 辅助的“同行评审”

这里有一个更高级的技巧：利用多个 AI 代理或助手进行质量把关。让一个 AI 生成代码，然后让另一个 AI 模型（或者在全新的对话中让同一个模型）来审查它：

*“请审查这段代码，找出潜在的 bug、性能问题和可维护性方面的不足，并提出具体的改进建议。”*

这种“多重校验”的方法，有时能发现单个 AI 实例可能会忽略的问题。

## 高阶技巧：自动化 PR 审查

### AI 驱动的代码审查工具

AI 代码审查工具的生态正在飞速发展，目前市面上已有不少选择：

- **GitHub Copilot**：在编码时提供建议，并能辅助审查代码变更（diffs）。
- **Cursor**：内置的后台 AI 可以在提交 PR 前分析代码变更。
- **专用工具**：许多与 Git 工作流集成的 AI 审查工具，例如 [CodeRabbit](https://www.coderabbit.ai/)（对开源项目免费）。

这些工具能帮你：
- 在 bug 进入生产环境前，高亮潜在风险。
- 提出代码改进和优化建议。
- 检查整个代码库的风格是否一致。
- 识别潜在的安全漏洞。

### 设置自动化审查流程

如果你正在使用 Cursor 或类似的 AI 编程环境，可以建立自动化的审查工作流：

*“请为这个项目的 Pull Request (PR) 审查创建一个核对清单（checklist），需要包含功能、性能、安全和代码风格等方面的检查项。”*

*“审查这份代码变更（diff），并指出其中所有潜在的问题或可改进之处：`[附上你的 git commit 信息]`”*

一些 AI 工具还支持关联你的 GitHub 账户，从而自动审查你仓库中的每一次提交或 PR。

## 融会贯通，提升效率

与 AI 一同进行测试和调试，目的不仅仅是修复问题，更是为了让你对自己的原型建立信心。当你将手动测试、AI 辅助调试和代码质量审查结合起来时，就构建起了一张强大的安全网，能在小问题演变成大麻烦之前将其捕获。

请记住：我们的目标不是要让你一夜之间成为测试专家，而是要帮你建立一个可靠的流程，从而交付更出色的原型。从简单的手动测试和基础的错误调试开始，随着你越来越熟练，再逐步引入更高级的技巧。

你的 AI 助手将全程为你保驾护航——从解释晦涩的错误信息，到生成你未曾想到的测试用例。这里的关键在于，学会提出正确的问题，并为 AI 提供充足的上下文，这样它才能给出真正有价值的回答。
